# kmodtui

A lazygit-style terminal UI for Linux kernel modules, for the tasks you do
rarely and never remember the commands for: see what's loaded, inspect a
module and its parameters, map devices to the modules driving them, check
Secure Boot and taint state, load and unload modules, blacklist them, load
them at boot and set their parameters.

kmodtui is a front-end, not a replacement. Every read and action is logged
with the **exact equivalent CLI command**, the Details view lists the
commands for whatever is selected, and every change shows exactly what will
run before it does, so you can always fall back to the command line.

## Install / build

Requires Go (latest stable). Targets Ubuntu (current LTS and newer).

```sh
make build            # bin/kmodtui, bin/kmodtui-helper and the polkit policy
./bin/kmodtui         # browsing works right away, no root needed

sudo make install     # needed for changes: see "Making changes" below
```

`make install` puts `kmodtui` in `/usr/local/bin`, `kmodtui-helper` in
`/usr/local/libexec` and the polkit policy in `/usr/share/polkit-1/actions`.
`sudo make uninstall` removes all three. For another prefix, build and
install with the same one: `make build PREFIX=/opt/kmodtui && sudo make
install PREFIX=/opt/kmodtui` (the helper path is compiled into kmodtui and
written into the policy).

`make check` runs the gofmt check, `go vet` and the tests.

The active panel has a green border; the selected row is highlighted in blue.
The bottom bar shows the keys that apply to the focused panel.

- **[1] Status**: kernel release, Secure Boot state, kernel taint. Focus it
  to see each taint flag explained and which modules caused it.
- **[2] Modules** tab: loaded modules with size and use count. Taint letters
  follow the name (`vboxdrv OE`). Press `A` for *all* modules:
  `●` loaded, `○` available but not loaded, `■` built into the kernel.
- **[2] Devices** tab: PCI and USB devices (root hubs omitted) and the module
  bound to each. `amdxdna?` means no driver is bound and `modules.alias`
  suggests that module; `—` means unbound with no candidate. `Enter` jumps to
  the module (switching to "all" if it is not loaded).
- **[3] Boot config** has two tabs. *Boot config*: the entries in the two
  files kmodtui manages, `/etc/modprobe.d/kmodtui.conf` and
  `/etc/modules-load.d/kmodtui.conf`; `d` removes the selected entry. *All
  files*: every `blacklist`, `options`, `install`, `remove`, `softdep`,
  `alias` and load-at-boot entry from all modprobe.d and modules-load.d
  directories (with the usual rule that a file in `/etc` hides a file of
  the same name in `/run`, `/usr/local/lib` or `/usr/lib`), each with its
  file. Entries in other files are shown read-only; kmodtui never edits
  them. The panel grows while you work in it, and `/` filters it.
- **[4] Changes**: follow-ups after a change, with `Enter` to fix them:
  "initramfs update needed" when `/etc/modprobe.d` changed after the
  initramfs was built, a blacklisted module that is still loaded, a module
  set to load at boot that is not loaded.
- **[0] Details**: everything about the selection in the last focused left
  panel. For a module:
  - **Why loaded**: the device it drives, a load-at-boot entry, another
    module's softdep, a mounted filesystem, or the loaded modules that need
    it and what those are ultimately for (`cfg80211` is needed by the mt76
    Wi-Fi stack, for `mt7925e`, which drives the Wi-Fi card). If nothing
    explains it, it says so.
  - `modinfo` fields, signature, dependencies, the devices it drives, and
    parameters with their current values (root-only values are marked
    `(root only)`).
  - **Config**: every config entry about the module, from any file, with
    file and line.
  - **Kernel log**: its last 20 kernel messages from this boot, such as
    firmware loading or probe errors.

  For a device: IDs, class, driver, module, modalias, USB interfaces, and
  its kernel log.
- **Command log**: every read kmodtui performed, as the command you would
  run yourself.

The bottom border of the Modules panel shows the position (`15 of 28`) and,
when active, the filter and the "all" mode.

## Keybindings

| Key | Where | Action |
| --- | --- | --- |
| `1` `2` `3` `4` | anywhere | Focus Status / Modules / Boot config / Changes |
| `0` | anywhere | Focus Details (to scroll it) |
| `Tab` / `Shift-Tab` | anywhere | Next / previous panel (includes Details and the log) |
| `j` `k` / `↓` `↑` | lists, Details, log | Move / scroll |
| `g` `G` / `Home` `End` | lists, Details, log | Top / bottom |
| `PgUp` `PgDn` | lists, Details, log | Page up / down |
| `[` `]` | Modules, Boot config | Previous / next tab |
| `/` | Modules, Boot config | Filter the current tab as you type |
| `Enter` / `Esc` | filter prompt | Keep the filter / clear it |
| `↓` `↑` | filter prompt | Move the selection while typing |
| `Esc` | Modules, Boot config | Clear an active filter |
| `A` | Modules tab | Toggle loaded / all modules |
| `u` | Modules tab | Unload the selected module |
| `l` | Modules tab | Load the selected module (in "all" mode) |
| `b` | Modules tab | Blacklist it, or remove its blacklist entry |
| `a` | Modules tab | Load it at boot, or stop loading it at boot |
| `p` | Modules tab | Parameters: list, change, remove an at-next-load value |
| `Enter` | Devices tab | Open the device's module in the Modules tab |
| `d` | Boot config | Remove the selected entry |
| `Enter` | Changes | Fix the selected item |
| `Enter` / `y` | confirmation | Run (`y` only when there are warnings) |
| `1` `2` | confirmation | Set a parameter now / at next load (toggle) |
| `Esc` / `n` | confirmation | Cancel |
| `R` | anywhere | Reload everything |
| `?` | anywhere | Show all keybindings (`Esc` closes) |
| `q` / `Ctrl-C` | anywhere | Quit |

The module filter treats `-` and `_` alike (`nvme-core` finds `nvme_core`),
as modprobe does. The device filter matches address, names, IDs
(`1002:1114`) and module names.

## CLI equivalents

| Feature | Equivalent command |
| --- | --- |
| Kernel release | `uname -r` |
| Secure Boot state | `mokutil --sb-state` (without mokutil: `od -An -tu1 /sys/firmware/efi/efivars/SecureBoot-8be4df61-93ca-11d2-aa0d-00e098032b8c`, last byte 1 = enabled) |
| Taint flags | `cat /proc/sys/kernel/tainted` |
| Loaded modules | `lsmod` (reads `/proc/modules`) |
| All available modules | `find /lib/modules/$(uname -r) -name '*.ko*'` and `cat /lib/modules/$(uname -r)/modules.builtin` |
| Module details | `modinfo <module>` |
| Current parameter values | `grep -H . /sys/module/<module>/parameters/*` |
| Load order (dependencies) | `modprobe --show-depends <module>` |
| Modules that need it ("Needed by") | `grep -w '<module>.ko' /lib/modules/$(uname -r)/modules.dep` |
| Modules using it right now | `ls /sys/module/<module>/holders` |
| PCI device and its driver | `lspci -nnk -s <address>` |
| USB devices and drivers | `lsusb -t`, `lsusb -d <vendor>:<product>` |
| Candidate modules for an unbound device | `modprobe --resolve-alias <modalias>` |
| kmodtui boot config | `cat /etc/modprobe.d/kmodtui.conf /etc/modules-load.d/kmodtui.conf` |
| All config files, overrides applied | `systemd-analyze cat-config modprobe.d`, `systemd-analyze cat-config modules-load.d` |
| Kernel messages about a module or device | `journalctl -k -b -r -n 20 --grep '\b(?:<module>)\b'` |
| Effective blacklist / options | `modprobe --showconfig \| grep -w <module>` |
| What a load or unload would do | `modprobe -n -v <module>`, `modprobe -n -v -r <module>` |
| Load / unload | `sudo modprobe <module>`, `sudo modprobe -r <module>` |
| Blacklist | `echo 'blacklist <module>' \| sudo tee -a /etc/modprobe.d/kmodtui.conf` |
| Load at boot | `echo <module> \| sudo tee -a /etc/modules-load.d/kmodtui.conf` |
| Set a parameter now | `echo <value> \| sudo tee /sys/module/<module>/parameters/<param>` |
| Set a parameter at next load | `options <module> <param>=<value>` in `/etc/modprobe.d/kmodtui.conf` |
| Rebuild the initramfs | `sudo update-initramfs -u` |

## Making changes

kmodtui itself never runs as root. Changes go through `kmodtui-helper`,
which kmodtui starts with `pkexec` after you confirm:

- **Confirmation first.** Every change opens a dialog with the exact
  `pkexec kmodtui-helper …` command, the commands it amounts to, and a dry
  run (`modprobe -n -v`) where that applies. Unloading a module that is in
  use, or that drives a storage, network, display, wireless or input device
  (directly or through a module that depends on it), or that provides a
  mounted filesystem, shows a warning, and then only `y` runs it.
- **Password prompt.** polkit asks for your password for every change (a
  desktop dialog, or a prompt in the terminal; kmodtui steps aside
  meanwhile). The policy deliberately uses `auth_admin`, not
  `auth_admin_keep`: a kept authorization would let the kmodtui process run
  any helper subcommand for a few minutes without asking.
- **What the helper can do** is fixed: `load`, `unload`, `set-param`,
  `blacklist`, `unblacklist`, `boot-load`, `boot-unload` and
  `update-initramfs`. It checks every module name against `modules.dep`,
  uses only `/usr/sbin/modprobe` and `/usr/sbin/update-initramfs`, and edits
  only `/etc/modprobe.d/kmodtui.conf` and `/etc/modules-load.d/kmodtui.conf`.
  Other files in those directories are never touched; lines you add to
  kmodtui's own files by hand are kept.
- **Initramfs.** Blacklists and options also reach early boot only after the
  initramfs is rebuilt. kmodtui shows "initramfs update needed" under Changes
  until it is.

You can also run the helper yourself, which is handy for scripts:
`pkexec /usr/local/libexec/kmodtui-helper blacklist pcspkr`. Run it without
arguments for the list of subcommands.

## Data sources

All read without root:

- `/proc/modules`, `/proc/sys/kernel/{osrelease,tainted}`
- `/sys/module/<name>/parameters/*`
- `/sys/bus/{pci,usb}/devices/*` (`driver`, `modalias`, IDs, class) and
  `/sys/bus/*/drivers/<driver>/module` (the module behind a driver, which can
  differ from the driver name: driver `xhci_hcd` is module `xhci_pci`)
- `/lib/modules/$(uname -r)/{modules.dep,modules.alias,modules.builtin}`
- `modinfo <name>` output, loaded lazily per module and cached until `R`
- Secure Boot: `mokutil --sb-state` if installed, otherwise the `SecureBoot`
  EFI variable
- Device names: `/usr/share/misc/{pci,usb}.ids` when present (USB devices
  prefer the names they report in sysfs)
- Config: `{/etc,/run,/usr/local/lib,/usr/lib,/lib}/{modprobe.d,modules-load.d}/*.conf`
- Kernel log: `journalctl -k`, which needs your user in the `adm` or
  `systemd-journal` group (Ubuntu's first user is in `adm`)

Notes:

- "Needed by" comes from `modules.dep`, which lists dependencies at any depth,
  so it includes indirect dependents.
- Candidate modules for unbound devices come from `modules.alias` only;
  aliases defined in `/etc/modprobe.d` are not considered.
- Some parameters are readable by root only; they show as `(root only)`.
Parameters marked "read-only now" can only be set at the next load.

## Development

```
cmd/kmodtui         entry point (-root DIR reads a fixture tree instead of /)
cmd/kmodtui-helper  the privileged helper (no flags, fixed subcommands)
internal/kmod       data sources, parsers and config editors, no UI
internal/helper     the helper's logic, testable against a temporary root
internal/ui         gocui views, layout, keybindings, dialogs and rendering
packaging/          polkit policy template
```

The UI uses [jesseduffield/gocui](https://github.com/jesseduffield/gocui)
(lazygit's fork), pinned to a master commit. Every filesystem read goes
through an injectable root and every command through an injectable runner,
so the parsers are tested against fixture trees captured from a real system
(see `internal/kmod/testdata/README.md`), and the UI is tested headlessly by
pressing keys and checking the rendered screen.
